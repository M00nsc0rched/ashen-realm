# ASHEN REALM — project rules for Claude Code

Original first-person dark fantasy RPG. Primary target: **web browser (WebGL)**, desktop and mobile; iPhone native
remains supported. Unity **6000.6.8f1**, URP 17.6, Input System 1.20, uGUI 2.6.
Current milestone: Checkpoint M, the redesigned valley, village, city, interiors and all five depths, all in
`Assets/Scenes/Prototype_Valley.unity`. See `docs/PROGRESS.md` for validation status and `docs/GRAVEBORNE.md` for the port's scope.
Do not expand scope beyond that plan (multiplayer, weather) unless asked.

## Art direction (match the user's reference screenshots)
Pixel-art painterly 3D: world rendered at 360 px height with hard pixels, posterised + Bayer-dithered; hand-made-looking
pixel textures (stone blocks, planks, cobbles, grass strokes, tiles); drooping-fringe pines, golden autumn trees, flower
and wheat cards; warm low sun, cool violet shadows, hazy blue distance; half-timbered houses, lanterns, windmill.
Long thin bars and a compass at the top centre, round emblem top-left, pause top-right, stone-ring touch controls.
- All world geometry uses `AshenRealm/PixelLit` (`M_World` opaque, `M_Foliage` cutout + wind). Colour/texture come from
  vertex data written by `MeshBuilder` via `Palette.SurfaceFor`; add new looks as texture layers in `PixelTextures`
  (append to `TexLayer`, never reorder) and families in `Pal`.
- Review visual changes with `BatchTasks.CapturePreviews` (emulates the pixel pipeline) before declaring them done.

## Golden rules
- The scene and its art are **generated**. Change generators in `Assets/Editor/`, then run
  `Ashen Realm > Generate Prototype`. Never hand-edit `Prototype_Valley.unity` or `Assets/Art/Generated/**`.
  Generated outputs are git-ignored (≈80 MB); regenerate after cloning.
- Do not run batch-mode Unity on a machine where the Editor is importing assets: it starved the Editor's shader
  compiler and crashed it twice. Ask the user to close the Editor, or wait until it is idle.
- Generation must stay deterministic (seed `ValleyGenerator.Seed`) and repeatable: update assets in place (keep GUIDs),
  rebuild the scene from an empty scene, delete only stale files inside generated folders.
- Gameplay reads input only through `IPlayerInput` (`PlayerInputHub`). Touch UI pushes into the hub; gameplay never
  references UI scripts or devices directly.
- Damage flows through `IDamageable.ApplyDamage(DamageInfo)`; mitigation via `IDamageFilter` on the same GameObject as `Health`.
- Animation is procedural and purely visual (`FirstPersonWeaponAnimator`, `KnightAnimator`); timing lives in gameplay code.
- Every serialized reference must be assigned unless the field has `[Optional]`. `Ashen Realm > Validate Prototype` enforces it.
- The world has thirteen zones far apart along X (`World/ZoneNumbers`): valley 0, Hollowgate 1, tavern 2, forge 3, chapel 4,
  depths 5-9, and the three valley homes appended at 10-12. Keep these ids stable; restrict depth checks to `FirstDepth .. FirstDepth + DepthCount`.
  `ZoneManager` keeps only the current zone active. Depths are generated by
  `DungeonGenerator` from `BiomeStyle` data; their props never collide (Graveborne rule), which keeps enemy steering simple.
- The depths bake their light too: `DungeonGenerator.BakeLight` turns every emissive face into a light over the biome's unlit stone.
  Keep depth ambients near neutral and put a biome's tint in `Unlit`, or warm fires turn to the zone's colour.
- The houses (`TavernGenerator`, `ForgeGenerator`, `ChapelGenerator`, `HamletGenerator`, all on `RoomGenerator`) are indoor zones: no sun; their light
  baked into the vertices with `MeshBuilder.Bake`, because the shader's point lights only reach a metre or two. Whoever stands in one is baked
  with the same light (`PeopleMeshes`). Under a roof the weapons stay at the door: `ZoneManager` calls `PlayerCombat.SetArmed`.
  The carried torch is a separate inventory choice and keeps its equipped state. `ArrivalGenerator` builds the closed, black southern
  tunnel and the waiting caravan; its threshold collider must remain solid even though no bars are visible.
- `AtmosphereController` carries sunset into evening as the player walks north. Entering the city sets `world_evening` in the soul's
  session flags; loading and returning to the valley must reapply it. First city arrival offers the torch once (`torch_presented`).
- Dialogues show a painted face from `UI/PortraitLibrary` when the speaker has one: `person_mood.jpg` in `Assets/Art/Menu/Portraits`, cut
  from the strips in `Vázlat_Kocsma`. Mood follows `Alignment`: 0 wary (Mortal), 1 warm (Hallowed), 2 hostile (Marked). The smith and the
  book-keeper have one picture, `person_0`, cut from the paintings in `Vázlat_Város`.
- What is for sale is `Catalog.Items`, with the art in `Assets/Art/Menu/Items` under the item's id. `UI/ShopPanel` shows it and `StoryDirector`
  (`IShopCounter`) decides; `PlayerClassRig` turns Graveborne's points into real-time numbers and shows the weapon in the hand.
- Text and balance from Graveborne live in `Story/Catalog` and `Story/StoryText`; the validator font-checks both and
  requires every enemy, NPC and encounter there to appear in the world.
- Performance budget (mobile browsers are the weakest target): fixed 360 px world render, two world materials,
  chunked static meshes, no realtime GI, one shadowed directional light, ≤3 permanent point lights in the active zone plus the carried torch.
- URP render scale must stay 1 (PixelCamera owns resolution; the validator checks it).
- WebGL build: `Ashen Realm > Build WebGL` or `BatchTasks.GenerateValidateAndBuildWebGL` with `-buildTarget WebGL`.
  Test via `tools/serve-webgl.ps1` (http://localhost:8080). See `docs/BUILD_WEBGL.md`.
- The game opens on `UI/MainMenu`, a canvas over the paused world in the same scene. Menus follow the sketches in the folder
  above the project (`Vázlat_*.jpg`, and `Vázlat_Kártyák` for the class cards): `MenuBuilder` uses their coordinates,
  `tools/prepare-menu-art.ps1` cuts their art into `Assets/Art/Menu` (committed, not generated). `BatchTasks.GenerateAndCaptureMenus`
  renders them for review without a web build.
- The class choice is `UI/ClassCarousel`, filled from `Catalog.Cards`. A card's numbers are the design's class sheet; the real-time
  values in `Catalog.Classes` are scaled from it. All six have real kits; `SoulKeeper.IsClassUnlocked` gates the last two and a locked card
  shows `CardLocked`. Check the unlock at the carousel, main-menu and story entry points, and save it in `MetaRecord.UnlockedClasses`.
- `PlayerProgression` owns saved stat growth, level, ability tiers, editable food and torch choice; class and gear bonuses must be composed
  once, without resetting bought growth. `InventoryPanel` displays and spends through that component. A continuous five-second hold on the
  HUD menu button opens `SecretStatsPanel` through `HoldMenuButton`; it uses unscaled time and must cancel on release, exit and focus loss.
- `PlayerTorch` animates eight frames from the supplied warm/cold strips through `AshenRealm/TorchStrip`, preserving alpha and point filtering.
  The witch and necromancer use the cold strip. `NpcIdleAnimator` gives people a living pose and drives the smith's hammer and impact sparks.
- Souls live in PlayerPrefs through `Story/SaveStore` (IndexedDB on the web, where `PlayerPrefs.Save` is what persists).
  Anything a soul can clear implements `ISavedState` with a unique key. Loading starts from a fresh scene, so state is only
  ever removed. Bump `SaveStore.WorldVersion` when world geometry moves, or old saves land inside walls.
- Game language is **Hungarian**. HUD strings go in `Core/GameText`, menu strings in `Core/MenuText` and `Core/InventoryText` (never a literal in a builder or
  script). The web build font covers only U+0020-U+007E and U+00A0-U+017F: no em dash, ellipsis or minus sign; the
  validator enforces it. Write HUD prompts in upper case there (no runtime case mapping).
- Mouse buttons only fight while the cursor is captured in desktop mode; in touch mode only the TÁMADÁS button attacks.
- Use only first-party Unity packages. Use the modern Input System (no `UnityEngine.Input`). HUD text uses legacy
  `UnityEngine.UI.Text` with the built-in `LegacyRuntime.ttf` (no TMP essentials import needed); menus use the same `Text`
  with Spectral (`Assets/Art/Fonts`, SIL OFL), the only third-party asset, added on the user's approval.
- Never claim compilation, validation or an iOS build succeeded without running it and reading the log.

## Layout
- `Assets/Scripts/{Core,Input,Player,Combat,AI,Interactions,UI,Story,World}` → assembly `AshenRealm.Runtime`
- `Assets/Editor/` → assembly `AshenRealm.Editor` (scene builder, validator, iOS configurator, batch tasks)
- `Assets/Editor/Generation/` → procedural mesh toolkit (`MeshBuilder`, `Palette`, `PropMeshes`, `ValleyGenerator`, `HudBuilder`, `MenuBuilder`, `ActorFactory`)
- Docs: `docs/ARCHITECTURE.md`, `docs/PROGRESS.md` (update after each checkpoint), `docs/BUILD_IOS.md`

## Validation (batch mode — the project must not be open in another Editor)
```
"C:\Program Files\Unity\Hub\Editor\6000.6.8f1\Editor\Unity.exe" -batchmode -quit -projectPath . ^
  -executeMethod AshenRealm.EditorTools.BatchTasks.GenerateAndValidate -logFile Logs/batch.log
```
Exit codes: 0 ok, 1 generation failed, 2 validation failed. Search the log for `error CS`, `[AshenRealm]` and `FAIL:`.
- On this PC, the parallel asset-import workers can crash before receiving an import request (native UDS filesystem initialization). Add `-refreshImportMode InProcess` to run imports serially in the main Editor process. This avoided the failure and the main project passed Checkpoint L without resetting Library.
- Batch Unity needs the Unity Hub running for its license (exit 198, "No valid Unity Editor license found" otherwise).
  The Hub is a Microsoft Store app: `explorer.exe "shell:AppsFolder\UnityTechnologies.UnityHub_2vrhnee42bhxm!UnityHub"`.
- Runtime playtest: `-executeMethod AshenRealm.EditorTools.BatchTasks.Playtest` **without `-quit`** (exit 0 ok, 3 failed;
  results tagged `[AshenRealm][Playtest]`). Extend `PlaytestRunner` when adding gameplay.
- Visual check: `BatchTasks.CapturePreviews` (world) and `BatchTasks.GenerateAndCaptureMenus` (menus) write PNGs to `Screenshots/`.
- If the project is open in the Editor, validate a copy (`robocopy` to `../_BatchValidation`, excluding Temp/Logs;
  delete `Library/EditorInstance.json`, `*.pid`, `*-lock` in the copy; re-sync `Assets/` before each run with `/XF *.meta`:
  an idle Editor has not written metas for new scripts yet, and mirroring would delete the copy's and break its scene).
  Run robocopy from PowerShell: Git Bash rewrites its `/E` switches. New assets get their metas in the copy, so copy those
  `.meta` files back into the project, or the project and the copy disagree on GUIDs.

## Conventions
- Namespaces `AshenRealm.<Folder>`; one public type per file (plain data records may share `Story/StoryTypes.cs`); private `[SerializeField]` fields, wired by the builder via `SceneWiring.Set`.
- Generated prop meshes: Y up, front faces −Z (knight parts are mirrored to face +Z at build time).
- Keep comments short and explain *why*. Match the existing style.
