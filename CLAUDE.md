# ASHEN REALM — project rules for Claude Code

Original first-person dark fantasy RPG. Primary target: **web browser (WebGL)**, desktop and mobile; iPhone native
remains supported. Unity **6000.6.8f1**, URP 17.6, Input System 1.20, uGUI 2.6.
Current milestone: the Graveborne integration (`docs/GRAVEBORNE.md`), all in `Assets/Scenes/Prototype_Valley.unity`. Do not expand scope
beyond that plan (multiplayer, weather, saves) unless asked.

## Art direction (match the user's reference screenshots)
Pixel-art painterly 3D: world rendered at 360 px height with hard pixels, posterised + Bayer-dithered; hand-made-looking
pixel textures (stone blocks, planks, cobbles, grass strokes, tiles); drooping-fringe pines, golden autumn trees, flower
and wheat cards; warm low sun, cool violet shadows, hazy blue distance; half-timbered houses, lanterns, windmill.
Long thin bars and a compass at the top centre, round emblem top-left, pause top-right, stone-ring touch controls.
- All world geometry uses `AshenRealm/PixelLit` (`M_World` opaque, `M_Foliage` cutout + wind). Colour/texture come from
  vertex data written by `MeshBuilder` via `Palette.SurfaceFor`; add new looks as texture layers in `PixelTextures`
  (append to `TexLayer`, never reorder) and families in `Pal`.
- Review visual changes with `BatchTasks.CapturePreviews` (emulates the pixel pipeline) before declaring them done.

## Golden rules
- The scene and its art are **generated**. Change generators in `Assets/Editor/`, then run
  `Ashen Realm > Generate Prototype`. Never hand-edit `Prototype_Valley.unity` or `Assets/Art/Generated/**`.
  Generated outputs are git-ignored (≈80 MB); regenerate after cloning.
- Do not run batch-mode Unity on a machine where the Editor is importing assets: it starved the Editor's shader
  compiler and crashed it twice. Ask the user to close the Editor, or wait until it is idle.
- Generation must stay deterministic (seed `ValleyGenerator.Seed`) and repeatable: update assets in place (keep GUIDs),
  rebuild the scene from an empty scene, delete only stale files inside generated folders.
- Gameplay reads input only through `IPlayerInput` (`PlayerInputHub`). Touch UI pushes into the hub; gameplay never
  references UI scripts or devices directly.
- Damage flows through `IDamageable.ApplyDamage(DamageInfo)`; mitigation via `IDamageFilter` on the same GameObject as `Health`.
- Animation is procedural and purely visual (`FirstPersonWeaponAnimator`, `KnightAnimator`); timing lives in gameplay code.
- Every serialized reference must be assigned unless the field has `[Optional]`. `Ashen Realm > Validate Prototype` enforces it.
- The world is seven zones far apart along X; `ZoneManager` keeps only the current one active. Depths are generated by
  `DungeonGenerator` from `BiomeStyle` data; their props never collide (Graveborne rule), which keeps enemy steering simple.
- Text and balance from Graveborne live in `Story/Catalog` and `Story/StoryText`; the validator font-checks both and
  requires every enemy, NPC and encounter there to appear in the world.
- Performance budget (mobile browsers are the weakest target): fixed 360 px world render, two world materials,
  chunked static meshes, no realtime GI, one shadowed directional light, ≤3 small point lights.
- URP render scale must stay 1 (PixelCamera owns resolution; the validator checks it).
- WebGL build: `Ashen Realm > Build WebGL` or `BatchTasks.GenerateValidateAndBuildWebGL` with `-buildTarget WebGL`.
  Test via `tools/serve-webgl.ps1` (http://localhost:8080). See `docs/BUILD_WEBGL.md`.
- Game language is **Hungarian**. Every player-facing string goes in `Core/GameText` (never a literal in a builder or
  script). The web build font covers only U+0020-U+007E and U+00A0-U+017F: no em dash, ellipsis or minus sign; the
  validator enforces it. Write HUD prompts in upper case there (no runtime case mapping).
- Mouse buttons only fight while the cursor is captured in desktop mode; in touch mode only the TÁMADÁS button attacks.
- Use only first-party Unity packages. Use the modern Input System (no `UnityEngine.Input`). UI text uses legacy
  `UnityEngine.UI.Text` with the built-in `LegacyRuntime.ttf` (no TMP essentials import needed).
- Never claim compilation, validation or an iOS build succeeded without running it and reading the log.

## Layout
- `Assets/Scripts/{Core,Input,Player,Combat,AI,Interactions,UI,Story,World}` → assembly `AshenRealm.Runtime`
- `Assets/Editor/` → assembly `AshenRealm.Editor` (scene builder, validator, iOS configurator, batch tasks)
- `Assets/Editor/Generation/` → procedural mesh toolkit (`MeshBuilder`, `Palette`, `PropMeshes`, `ValleyGenerator`, `HudBuilder`, `ActorFactory`)
- Docs: `docs/ARCHITECTURE.md`, `docs/PROGRESS.md` (update after each checkpoint), `docs/BUILD_IOS.md`

## Validation (batch mode — the project must not be open in another Editor)
```
"C:\Program Files\Unity\Hub\Editor\6000.6.8f1\Editor\Unity.exe" -batchmode -quit -projectPath . ^
  -executeMethod AshenRealm.EditorTools.BatchTasks.GenerateAndValidate -logFile Logs/batch.log
```
Exit codes: 0 ok, 1 generation failed, 2 validation failed. Search the log for `error CS`, `[AshenRealm]` and `FAIL:`.
- Batch Unity needs the Unity Hub running for its license (exit 198, "No valid Unity Editor license found" otherwise).
  The Hub is a Microsoft Store app: `explorer.exe "shell:AppsFolder\UnityTechnologies.UnityHub_2vrhnee42bhxm!UnityHub"`.
- Runtime playtest: `-executeMethod AshenRealm.EditorTools.BatchTasks.Playtest` **without `-quit`** (exit 0 ok, 3 failed;
  results tagged `[AshenRealm][Playtest]`). Extend `PlaytestRunner` when adding gameplay.
- Visual check: `BatchTasks.CapturePreviews` writes PNGs to `Screenshots/`; read them to review art changes.
- If the project is open in the Editor, validate a copy (`robocopy` to `../_BatchValidation`, excluding Temp/Logs;
  delete `Library/EditorInstance.json`, `*.pid`, `*-lock` in the copy; re-sync `Assets/` before each run with `/XF *.meta`:
  an idle Editor has not written metas for new scripts yet, and mirroring would delete the copy's and break its scene).

## Conventions
- Namespaces `AshenRealm.<Folder>`; one public type per file (plain data records may share `Story/StoryTypes.cs`); private `[SerializeField]` fields, wired by the builder via `SceneWiring.Set`.
- Generated prop meshes: Y up, front faces −Z (knight parts are mirrored to face +Z at build time).
- Keep comments short and explain *why*. Match the existing style.
